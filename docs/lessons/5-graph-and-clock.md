- **Lessons:**
  - Timing a worker message with the two sides' clocks measures the page's queue, not the copy: with software WebGL at 9 frames a second every "copy" read about 115 ms. Time the first read of `event.data` (when the browser rebuilds the message) and the patch on the page, and the `postMessage` call in the worker, separately. `docs/SYSTEMS.md` ("Speed budget") says how the figures were taken, so later parts measure the same way.
  - A browser check that samples on wall-clock timers assumes a frame rate; CI's software WebGL runs at 5 to 10 frames a second. Sample frame by frame (`requestAnimationFrame` in the page) with a time limit, and make a tick last several frames. The `scene` group does this now (`tools/checks/scene.mjs`). The first CI run still went red on the one timer left: the `layout` keyboard test read the pause button 200 ms after pressing it, and on CI (4 frames a second) the top bar hadn't redrawn. It now waits for the state (`tools/checks/layout.mjs`). A browser check waits for what it asserts, never for a fixed time.
  - `tools/join.mjs` takes a system's files from the first paragraph of its note only, so a note that names its files further down lists none and the graph can't find them. Name every file in the first paragraph; worth a line in the `feature` playbook's notes step at the next tidy.
  - An activity that reuses an id across trips vanishes under deltas (the page drops the old one at its end and never hears of the new). The rule "an activity never changes once started; a new trip is a new id" is in `docs/systems/commands.md`; part 3's gardener must keep it.
